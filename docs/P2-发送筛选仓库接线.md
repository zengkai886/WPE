# P2：发送列表、筛选触发与仓库事件

日期：2026-09-18

## 已完成

- **目标侧发送列表执行器**：`StartSend`、`StartSendList`、`StopSendList` 已接入 `HeadlessCore`。只执行启用的发送项，按每项的封包顺序和循环次数发送；`LoopINT` 可中断等待；停止和目标退出会唤醒并回收执行线程。
- **发送计数与运行状态**：每次目标侧发送都会更新执行/成功/失败计数；`Stats` 的发送运行位与停止状态由同一执行器维护。重复启动不会创建第二个执行线程。
- **筛选规则触发**：筛选的 `ExecuteType=Filter` 仍以内联递归执行；`Send` 生成目标侧发送触发；`WareHouse` 生成带筛选后字节的 `StoreAdded` 事件。机器人触发仍不执行。
- **WinSock 全入口联动**：普通 `send/sendto/recv/recvfrom`、WSA scatter/gather 以及 x86 的 `WSARecvEx` 都经过统一触发分发；触发失败不会改变原始 WinSock 返回路径。
- **仓库事件落库**：外壳原生数据层新增 `DataService::ApplyStoreEvent`，严格解析事件类型、GUID、BLOB 和尾字段，在 SQLite 事务中追加并按 `StoresLimit/StoresLimit_Value` 删除最旧条目，然后发布原 `feed:replace`。找不到仓库的迟到事件会被安全丢弃。
- **数据线程入口**：`DataWorker::SubmitStoreEvent` 提供仅供原生事件管线使用的入口，不注册为浏览器 RPC；带 1 MiB 单帧和 16 MiB 待处理事件字节上限。
- **有界队列与可观测丢弃**：仓库事件队列满时优先淘汰最旧的待处理仓库事件并通过其完成回调报告；目标触发队列为无锁有界栈，无法入队时采用不阻塞 detour 的 drop-new 策略，累计次数可由 `DroppedTriggerCount()` 查询。两种策略都不把阻塞/锁竞争带入目标网络调用。

## 明确未完成

- 当前宿主 `main.cpp` 尚未建立生产用 `ShellIpcSession` 与注入生命周期，因此 Vue 的 `startSendList/stopSendList` RPC 仍未注册；目标端命令和原生数据事件接口已经可用，但尚未接到实际 UI 按钮。
- 真实目标注入、代理/抓包来源、实时 Stats/FilterLog 到 Vue 的完整推送仍不在本 P2 收尾中。
- 机器人运行时（`StartRobot`、`StartRobotList`、`StopRobotList`、键鼠动作和调度）明确不加入本阶段；机器人数据和指令编辑保持原有离线接线。
