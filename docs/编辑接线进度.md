# 第四段：编辑器数据接线

本段继续用户更新版《WPE x64 C++ 重写工程文档》，沿用 C++20 / Win32 / WebView2 / 全部原 Vue。目标是让原编辑器操作真实进入 C++ 数据逻辑和 SQLite，不重绘界面，不把编辑完成冒充运行引擎完成。

## 本段交付范围

### 机器人指令编辑

- 原 `openRobotEdit / closeRobotEdit / getRobotInstructions / addRobotInstruction / robotInstructionAction / saveRobotEdit` 六个入口。
- 九类指令：发送列表、延迟、循环开始、循环结束、键盘、鼠标、发送选中封包、系统 Socket、启用/禁用开关。
- 插入位置、移动、删除、清空、名称/指令内容校验；保存时检查引用与循环关系、返回原 `badIndex`。
- 原指令名称和描述的本地化键、数据返回格式；D/N/B/P/X GUID 与 .NET 数字空白的回归案例。
- 草稿取消不写父列表；保存事务成功后更新父列表指令数量；保存保留当前启用标志。
- **不含**指令执行、键鼠操作、定时/并发调度、真实封包发送。

### 发送集与封包编辑

- 发送集读取、复制、移动、删除、确认清空；父发送项保存后落库。
- 原 `SendCollection` 和旧 `SendList` 明文 XML 导入，使用 Windows 文件选择框，后台 XmlLite 流式解析；原成功通知含标题和文件路径。
- 原 `PacketEdit` / `HexView` 编辑发送集中的字节和 Socket，使用原 Base64 数据契约，保存后刷新原预览。
- **仅支持 `list=send` 来源**。捕获列表、代理列表来源及实际发送尚未接；不返回假成功。
- XML 加密/密码提示、导出、发包转发和执行进度尚未接。

### 仓库条目

- 原条目移动、复制、删除、确认清空；按配置限制保留条目。
- 原明文 `.whs` XML 导入，完成数据库事务后更新原仓库数量和内容。
- 配合已有改名、BLOB 读取、延迟预览、复制文本接口。系统剪贴板写入尚未接。
- 仓库条目操作是即时保存，不是关闭窗口时统一回滚。

## 必须保留的原源码细节

原 `OpenSendEdit_ById` 只复制集合，已有 `PacketInfo` 对象仍共享；原 `CopySend` 也共享已有封包对象。因此：

1. 发送集的新增导入、删项、移动、清空属于集合草稿；不保存父窗口就丢弃这些集合变化。
2. **修改已有封包的字节/Socket 后，再取消外层发送窗口，不会撤销内存中的封包修改。**
3. 封包编辑本身不立即写数据库；保存父发送项或后续保存整个发送列表时才持久化。

本段按上述实际行为实现并对拍，没有因为“取消通常应该回滚”而擅自改变语义。上一段笼统的“工作副本”描述不能解释成所有嵌套封包字段均隔离。

## 错误与当前差异

- 未完成分支明确报错；没有执行器时不产生虚构的运行计数或成功发包。
- 导入先完整解析、再修改草稿/提交数据库。损坏 XML 或错误 Socket 不会半途写入；原版部分错误路径可能保留先前条目。这是**已知异常输入行为差异**，不能宣称此类输入完全等价。
- 禁止 DTD，XML 嵌套深度限制为 64；未验收依赖 DTD 或更深嵌套的外部文件。没有新增文件大小上限，65 MiB 合法文件已有回归。
- 文件选择框标题与通用删除确认文字仍需按所有语言逐项对齐；实际 Windows 文件选择框尚未人工逐场景回归。
- 隐藏窗口置顶自测在上一段及本段早期均有偶发失败，后续通过；根因尚未定位，不宣称所有窗口体验完全稳定。
- 本段扩展原 Vue 自测后，早期 30 秒预算不足；自测总预算改为 90 秒，外层等待 105 秒。保留失败记录，不把测试超时伪装成成功。

## 逐层验证

1. **原版业务参照**：未修改原业务程序集实际运行生成 184 条连续编辑调用。规范化生成的 ID，逐项比较完整返回对象。不是拿 C++ 自己的输出当标准。
2. **C++ 编辑回归**：每架构 229 项检查，包括上述 184 条，以及数据库锁定回滚、重开、草稿取消、封包别名、通知、Unicode 数字/GUID、损坏/DTD XML、65 MiB 文件。
3. **原 Vue 界面链路**：真实 WebView2 加载原预构建资源；点击发送导入、原 HexView 键入 `AA`、修改 Socket 为 `99`、保存；仓库导入/取消清空/改名；机器人插入循环开始→延迟 25ms→循环结束、保存、追加草稿后取消；关闭重开检查相同内容。
4. **选择文件测试边界**：自动测试使用固定路径选择入口，随后经过真实文件读取、解析、原 RPC、数据库、列表和通知。**这不是对 Windows 选择文件对话框本身的自动点击验收。** 正常模式仍调用原生 `IFileOpenDialog`，不会使用固定测试路径。
5. **已有功能回归**：每架构 7/7 CTest，包含原 440 项数据检查、120 条滤镜参照、消息桥/线程；另保留 74,684 条协议参照、76,618 条断言、600 个封包反向解码和 6,416 条队列状态对拍。
6. 原 555 个前端/远程文件、其中 70 个 Vue 文件逐个哈希不变。产品不调用原 C# 业务后端。

证据位于 `evidence/editor-*`。源码 ZIP 还应在不含 `.git` 的新目录重建，发布包独立启动测试；实际发布记录以对应 manifest 的 `result` 为准。历史 `data-*` / `protocol-*` 不是本段新结果。
