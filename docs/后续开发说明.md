## 3. 当前已经实现并真实接线的范围

### 3.1 原界面与宿主

- 原 Vue3、70 个 Vue 文件和全部静态资源保留。
- 原生 C++ WebView2 宿主、五消息前端桥、文件选择授权、密码框、剪贴板和首次/重启页面测试已有实现。
- WebView2 Runtime 是外部运行环境，不应打包成业务源码或用假页面替代。

### 3.2 数据与原格式

- SQLite 20/20 表。
- 四类父列表、滤镜/发送/机器人/仓库、白名单、黑名单、代理账号、自动入库、双向映射、WPC 服务端/规则/通知等数据接线。
- `.fp/.sp/.rp/.whp/.sc/.whs/.wl/.bl/.pa/.pas/.pml/.pmr/.sb` 的明文及原 AES 兼容路径。
- `.sb` 14/14 分组，原 XML 字段顺序、空/null、BOM、换行、密码派生和 AES-CBC 行为已有黄金测试。
- 当前注册约为 126 个数据接口 + 10 个宿主接口；原清单共 217 个接口，仍有 81 个未注册。注册数量不是功能完成率。

### 3.3 IPC、目标核心和注入基础

- ctl/pkt/evt 三条真实 Windows 命名管道、当前用户 ACL、overlapped I/O、取消和帧上限。
- Shell/Target v4 会话、Hello、Ping、watchdog、Detach、错误应答、pkt/evt 接收线程。
- 事件通道为原版口径的有界队列：8192 条 / 16 MiB，丢最旧、累计并生成日志，唯一后台线程写 evt；事件生产者不直接阻塞写管道。
- 目标无头核心支持 HookFlags、Filters、Runtime、Sends、Robots 五类快照，统计、ResetStats、HookState/Fatal/Stats 事件。
- x64/Win32 同位数 `LoadLibraryW + WpeStart` 原生注入基础和生产 `wpe64-hook.dll`；`DllMain` 不做业务初始化。

### 3.4 MinHook 与真实原始抓包

- 官方 MinHook 1.3.4 已静态纳入。
- 生产 `HookManager` 使用进程全局引用计数，只操作自己注册的目标；停用、移除或反初始化失败时保留状态供重试。
- 已接 13 个原版 Winsock 签名规则：
  - wsock32：`send/sendto/recv/recvfrom`
  - ws2_32：`send/sendto/recv/recvfrom/WSASend/WSASendTo/WSARecv/WSARecvFrom`
  - Win32：`WSARecvEx`
  - x64 按原版规则跳过 `WSARecvEx`
- detour 只做安全读取、不可变字节复制、原子计数和入环；地址解析、PacketFrame 编码、pkt 管道写入在专用线程完成。
- 64 MiB / 65536 条封包丢旧环、每批最多 256 条 / 1 MiB、极速模式、11 项实时计数和累计 Dropped 事件已接。
- 已处理无效指针、超大载荷、写端失败、端点解析失败、外壳断开和半帧超时；这些失败计入丢弃而不伪装成成功抓包。
- 卸钩时先在共享 admission gate 下清除 active owner，再停用 hook，等待已进入 detour 的调用退出；若阻塞 `recv` 超时则保留 owner/trampoline，并由安全退休线程重试，避免释放后跳转。

### 3.5 目标侧滤镜执行链

- `FilterEngine` 从 Filters/Runtime 快照编译运行表，经原子裸指针发布；封包热路径只使用原子读者计数和指针读取，不获取发布互斥锁，旧表在发布线程观察到静默点后回收。相同 GUID 的执行/递进状态及全局计数跨表共享原子运行态，避免发布或 Reset 与并发封包互相覆盖。
- 已实现启用状态、12 类函数、socket、端口、长度、包头门控，普通/高级匹配、半字节通配符、排除位置、绝对/相对位置、Priority/Sequence 顺序。
- 已实现 Replace、Change、Intercept、NoModify_Display、NoModify_NoDisplay，以及修改、递进、进位、连续递进和随机位置。
- 已实现 Filter→Filter 联动执行及固定深度循环保护；Send、WareHouse 两种联动仍待实现，且不会被伪计为执行成功。Robot 联动及机器人运行执行器已按用户要求移出交付范围。
- 同步 `send/sendto/recv/recvfrom`、同步 `WSASend/WSASendTo/WSARecv/WSARecvFrom` 与 Win32 `WSARecvEx` 已接真实改写/拦截；原始和修改后字节及动作进入 PacketFrame，NoModify_NoDisplay 不进入 pkt 队列。
- 滤镜执行次数、六项全局计数、ResetStats 和 FilterLog 事件已接；FilterLog 随封包工作项一次入环，由 writer 线程编码并发送，detour 不再同步构造 IPC 或调用事件发送器。极速模式仍执行滤镜和计数，但不产生 FilterLog/pkt 帧。
- 端口门控在封包 detour 只查固定大小原子端点缓存；`bind/connect/WSAConnect/accept/WSAAccept/getsockname/getpeername/closesocket` 生命周期 hook 只合并或清除端口元数据，不做字符串格式化、IPC 或额外同步查询。普通 `connect/accept` 路径的首个 connected 封包和 socket handle 复用已覆盖；通过 `ConnectEx/AcceptEx` 扩展函数、且应用未经过上述生命周期 API 的首包仍须单独补扩展函数注册。
- 非空 overlapped WSA 请求仍保持原缓冲和原异步生命周期，不使用临时改写缓冲；其完成期滤镜需要独立的 overlapped 上下文设计，不能把同步实现冒充为已完成。

## 10. 不可破坏的实现约束

- 生产代码保持 C++20；原 C# 只作对照。
- 保留全部原 Vue 和资源，不用新界面掩盖未实现功能。
- detour 不做文件、数据库、同步管道写、UI 或字符串格式化。
- 跨线程数据必须有明确所有权和不可变生命周期。
- 所有队列有界、满时丢旧并计数；不能用阻塞目标网络线程换取“零丢包”。
- 帧写超时后不得继续复用可能已有半帧的流。
- 卸钩不能在仍有已进入 detour 的调用时释放 trampoline 或 owner。
- x64/Win32 必须跑同一套适用测试，架构差异必须明确记录。
- 任何“完成”声明必须有当前源码、当前构建和真实运行证据。
