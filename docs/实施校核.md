5. 原前端文件、原预构建资源与远程页面已从用户 ZIP 提取；555 文件逐个记录 SHA-256，包含 70 个 Vue 文件。

## 3. 对照源码后需要修正的技术示例

这些修正服务于文档的“行为等价/二进制兼容”，不改变用户功能目标。

| 文档位置 | 问题 | 实施处理 |
|---|---|---|
| 标题依据 v2.2 | 原 ZIP 的程序集与前端标识为 2.3，README 仍标 2.2 | 锁定用户 ZIP 哈希及实际源码，不拿另一个网上版本替换 |
| 3.1 字符串返回 `std::string` 却要求 null | 普通字符串无法区分 null 与空；C# 输入还能含未配对 UTF-16 代理项 | 使用 `optional<u16string>` 作为兼容边界，线上仍为 UTF-8；异常编码替代规则对照 Framework 4.8 |
| 目录 GUID/RFC 4122、Guid 骨架 | 原 `Guid_` 写的是 `i32(16)` 加 .NET 混合字节序，不是直接输出 16 个网络序字节 | 规范表示与线上排列显式转换，已有黄金测试 |
| 3.2 帧上限 | 原 reader 实际按有符号 i32 检查负值/上限 | 拒绝负长度、截断头、截断内容；完全 EOF 才返回空 optional |
| 3.3、16.2 的 mutex 队列“永不阻塞” | mutex 可能等待；源实现主要保证不等管道、不等消费者 | 不把短临界区称为无锁，也不承诺纳秒时延；队列模块后续单独实现并压测 |
| 6.2 只原子替换裸指针 | 缺少旧快照的读者生命周期管理；原子发布本身不防释放后访问 | 实现快照时必须补充明确的读者所有权/回收机制，不能照抄裸指针示例 |
| 16.2 发送钩子 | `newBuf` 没接收滤镜结果，示例却把空缓冲送给原函数 | 实现时显式返回动作与缓冲；未修改时使用原数据，并测试目标实际收到的字节 |
| 5.1、16.2 注入示例 | 无失败清理、无超时；LoadLibrary 返回也不等于业务入口已初始化 | 后续实现资源 RAII、结果检查和入口握手；进程/位数/唤醒时序需实测，不能把示例当成完备注入器 |
| 9.2 “界面工作量≈0” | 页面可以原样保留，但宿主、双向桥、文件框、窗口行为和业务都仍要实现 | 不改页面；单独验收完整桥及所有原业务，不能只展示 UI |
| 9.2 运行时、2.1 静态依赖 | 不能把 WebView2 Runtime 当成已静态装入单个 exe | 发布阶段检测并说明 Runtime 依赖，另行验证单文件启动器及解包清理 |

源码参考：原 `IpcProtocol.cs`、`PacketFrame.cs`、`PacketRing.cs`、`ConfigSnapshot.cs`、`ShellForm.cs`。前两份原文件已按原字节保存于测试参考目录，每次运行会校验哈希。
