# WPE x64 全 C/C++ 重写工程文档

**核心（DLL 注入 + Winsock 钩子）+ 界面（复用原 Vue 前端 · WebView2 宿主）· 行为等价版**

> 依据原始源码 `WinsockPacketEditor-master`（C#/.NET，v2.2）逐模块映射编写。
> 本文档是一份**可照着做出来的完整工程蓝图**：包含架构、工程骨架、协议规范、钩子语义、
> 数据模型、UI 方案、验证方案、里程碑与风险清单。

## 0. "一模一样"的定义与验收标准（先读这节）

原版是一个 C# 程序，重写成 C++ 后**不可能逐字节一致**。本文档把目标定义为**行为等价**：

> **行为等价**：对同样的输入（目标程序、封包序列、滤镜配置、操作序列），
> 两个版本产生**可对拍的输出**——抓到的封包集合一致（时间戳归一化后）、
> 滤镜改写结果一致、拦截/放行语义一致、界面呈现的数据一致。

三条硬性验收规则（贯穿所有里程碑）：

1. **同一个测试场景，两个版本各跑一遍，输出逐项对拍**（对拍方法见第 13 节）。
2. **目标进程的红线一条都不能破**：不阻塞目标的收发、不打开任何文件、
   外壳没了必须卸钩、不改目标 DPI（原代码风险清单 R4/R8）。
3. **协议与配置格式与原版二进制兼容**：IPC 帧格式、滤镜快照字段顺序、
   封包帧格式逐字段一致（见第 4、6 节），保证两个版本可以共用同一套测试夹具。

**与原版的允许差异（明确列出，其余一律照搬）：**

| 项目 | 原版（C#） | 本版（C++） | 说明 |
|---|---|---|---|
| 钩子库 | EasyHook 2.7.7097 | MinHook（x86/x64） | 同为内联钩子，语义一致 |
| WSARecvEx x64 | 刻意不钩（指针截断 bug） | 默认同原版不钩；可选按正确签名 `int WSARecvEx(SOCKET, char*, int, int*)` 钩 | 原版行为保留为默认 |
| 界面 | WebView2 + Vue3 前端 | **复用原 Vue3 前端 + WebView2 宿主**（C++ 外壳；Qt 原生为备选，见 9.4） | 观感与原版一致；这是用户已确认的主方案 |
| 注入器 | EasyHook CreateAndInject | CreateRemoteThread + LoadLibrary | 语义一致，见 5.1 |
| 目标进程足迹 | CLR + 托管程序集 | 单个原生 DLL（更小，算改进项） | 原版 R2 风险自动缓解 |

## 1. 总体架构

### 1.1 两种工作模式

```
【注入模式】
 ┌──────────────────────────┐       3 条命名管道         ┌──────────────────────────┐
 │  外壳（C++ 程序，64位）     │ ◄───────────────────────► │  目标进程（任意位数）      │
 │  · 界面 / 滤镜编辑        │   WPE64-{sid}-ctl         │  · WPEHook.dll（被注入）  │
 │  · 代理服务器(可同时开)   │   WPE64-{sid}-pkt         │  · 13 个 Winsock 钩子     │
 │  · 数据库 / 日志 / 仓库   │   WPE64-{sid}-evt         │  · 无头核心(4 线程)       │
 │  · 归属地 / 统计          │                           │  · 滤镜引擎 / 执行器      │
 └──────────────────────────┘                           └──────────────────────────┘

【代理模式】
 客户端/设备 ──SOCKS5──► 外壳(Qt) ──► 目标服务器
                          │
                   滤镜 + 可选 HTTPS 解密(OpenSSL)
```

- **注入模式**：外壳把 `WPEHook.dll` 注入目标进程，目标进程内部钩住 Winsock 收发，
  封包经 3 条命名管道回传外壳显示/编辑/重放。目标内**不建窗口、不开数据库、不写文件**。
- **代理模式**：外壳自身作为 SOCKS5 代理服务器（TCP + UDP），中途看包/改包/解 HTTPS。
  代理与注入可同时开启，共用同一套滤镜引擎与统计。

### 1.2 进程与模块划分

```
wpe64-app/                          # 外壳 C++ 程序（WebView2 宿主，主进程）
wpe64-hook.dll                      # 注入 DLL（x86 / x64 各一份）
wpe64-launcher.exe                  # 启动器（自解压 + 提权启动外壳）
wpe64-target-test.exe               # 测试靶子（对应原 WPETarget32）
```

### 1.3 核心数据流（注入模式，按原版 WpeCore 逐条对照）

```
目标进程收发线程（钩子）：
  钩子体拷贝缓冲 → DoFilterList(滤镜引擎) → 拦截? → 假成功/假0
  → OnPacket：两道早退 → CountPacketInfo → SpeedMode? → 入 PacketRing（永不阻塞）
写线程：ring 批量出队(≤256条/1MB) → getsockname/getpeername 解析地址 → PacketFrame 编码 → pkt 管道
事件线程：evt 队列(≤8192条/16MB) → evt 管道（日志/仓库/统计/丢包）
控制线程：ctl 管道读命令 → Dispatch → 应答；任何命令都刷新心跳
心跳线程：1 秒一拍；顺带发 Stats；连续 3 秒收不到 Ping → 自行卸钩 → 核心休眠
```

## 3. 公共基础库（src/common）

### 3.1 二进制编解码（对应 IpcWriter / IpcReader，逐字段兼容）

字段一律**小端**。字符串 = `i32 字节数` + UTF-8，null 写 `-1`（与空串区分）。

```cpp
// ipc_codec.h —— 接口与 C# 版一一对应
struct IpcWriter {
    std::vector<uint8_t> buf; size_t len = 0;
    void U8(uint8_t v);  void Bool(bool v);  void I32(int32_t v);  void I64(int64_t v);
    void Str(const char* v);      // nullptr → I32(-1)
    void Bytes(const uint8_t* p, int32_t n);  // nullptr → I32(-1)
    void Guid(const uint8_t g[16]);
    std::vector<uint8_t> ToArray();
};
struct IpcReader {
    const uint8_t* p; size_t pos, size_;
    uint8_t U8(); bool Bool(); int32_t I32(); int64_t I64();
    std::string Str();                 // 读到 -1 → 空 optional
    std::vector<uint8_t> Bytes();
    void Guid(uint8_t g[16]);
};
```

**红线**：加字段改两处（编码 + 解码），字段顺序错了不会报错、只会行为错——
每改一次协议就 `Version++`（当前 v4），两端对不上直接拒绝，不兼容、不猜。

### 3.2 帧读写（对应 IpcFrame）

- 分帧：`u32 小端长度` + 载荷。**一次 Write 写完长度+内容**，禁止拆两次写
  （两个线程同时写会交错，且无法还原）。
- 读：先读满 4 字节头，再读满载荷；管道正常关闭返回空，读到一半断报错。
- 上限：控制帧 1 MB（`MaxControlFrame`）、封包帧 16 MB（`MaxPacketFrame`）。

```cpp
bool IpcFrameWrite(HANDLE pipe, const std::vector<uint8_t>& payload); // 单次 WriteFile
std::optional<std::vector<uint8_t>> IpcFrameRead(HANDLE pipe, size_t maxLen);
```

### 3.3 有界环形缓冲（对应 PacketRing，语义逐条照搬）

- 上限：**65536 条 / 64 MB**（原版参数，先照搬，后续按验证矩阵实测定）。
- `Enqueue` **永不阻塞**：先入再挤，满了从队头丢最旧的并计数
  （单条超大的也进得来——挤完只剩它自己）。
- `DequeueBatch(maxCount, maxBytes, waitMs)`：无数据最多等 waitMs；
  Reset 与 Wait 之间要再看一眼队列，防"明明有数据却睡满一拍"。
- `Dropped` 计数随事件上报，界面上显示"丢弃 N"。

### 3.4 目标进程内线程纪律（原版 R8，必须写进代码规范）

- 只用**专用线程**（std::thread），**禁止线程池**——线程池是目标进程自己的资源。
- 钩子线程（目标自己的收发线程）上**只允许**：拷贝缓冲 + DoFilterList + 一次入环。
  禁止：写管道、等锁超过纳秒级、格式化字符串、查归属地、起线程。
- 目标进程内**不打开任何文件**，唯一的句柄是 3 条管道（原版第四节第 8 条）。

## 4. IPC 协议规范（v4，二进制兼容）

### 4.1 管道命名与安全

```
命名管道（NPFS，走 \\\\.\\pipe\\，不经过 ws2_32 —— 天然不会被自己的钩子钩到）：
  WPE64-{sessionId}-ctl     # 控制：双向，外壳服务端
  WPE64-{sessionId}-pkt     # 封包流：目标→外壳，单向
  WPE64-{sessionId}-evt     # 事件流：目标→外壳，单向
sessionId = 注入前由外壳生成的 GUID（不能等目标 PID，注入后才知道 PID）
```

**ACL 必须做**：管道服务端 ACL 只给当前用户 FullControl
（对应原版 `PipeSecurity`——管道那端能调本机强力方法，不能让他人连上）。

### 4.2 控制通道命令表（外壳 → 目标）

| 命令 | 值 | 载荷 | 应答 |
|---|---|---|---|
| Hello | 1 | i32 协议版本 | Ok + i32 版本 + i32 PID + bool is64；版本不符 → VersionMismatch |
| Ping | 2 | 空 | Ok |
| StartHook | 3 | 空 | Ok（钩子装好后置位唤醒事件，见 5.5） |
| StopHook | 4 | 空 | Ok |
| SetConfig | 5 | u8 kind + bytes 载荷 | Ok / Error |
| SendPacket | 6 | i32 socket, i32 type, str from, str to, bytes | Ok + bool sent |
| GetSocketInfo | 7 | i32 socket | Ok + str from + str to |
| Detach | 8 | 空 | Ok（应答发出后 50ms 收尾卸钩断管道） |
| GetFootprint | 9 | 空 | Ok + 模块清单（诊断用） |
| ResetStats | 10 | u8 掩码（ResetWhat） | Ok |
| StartSend | 20 | guid | Ok |
| StartSendList | 22 | 空 | Ok |
| StopSendList | 23 | 空 | Ok |
| StartRobot | 24 | guid + i32 filterSocket | Ok |
| StartRobotList | 26 | 空 | Ok |
| StopRobotList | 27 | 空 | Ok |

```
ConfigKind:  HookFlags=1, Filters=2, Runtime=3, Sends=4, Robots=5
ResetWhat(位或):  FilterStats=1, PacketCounters=2, SendCounts=4, RobotCounts=8
Status:  Ok=0, Error=1, VersionMismatch=2
```

**关键语义**（全部来自原版，必须照做）：
- 收到**任何**命令都刷新心跳时间戳（Ping 与请求共用一条通道，处理慢时不能误判"外壳没了"）。
- `Detach`：先把应答发出去，再收尾（否则外壳等不到回复）。
- `ResetStats` 的掩码语义：统计数据页"归零"只清滤镜组；数据页"清空"清封包计数；
  发送/机器人各自只清自己——**复位必须发到目标做**（计数在目标里递增，只清外壳会被下一拍盖回）。

### 4.3 事件表（目标 → 外壳，evt 管道）

| 事件 | 值 | 载荷 |
|---|---|---|
| Log | 1 | str funcName, str content |
| FilterLog | 2 | str filterName, i32 action, i32 matchNum, i32 packetType, i32 packetLen |
| Stats | 3 | 见下 |
| Dropped | 4 | i64 累计丢弃数 |
| HookState | 5 | bool on, bool SupportWS1, bool SupportWS2, bool SupportMsWS |
| StoreAdded | 6 | guid 仓库ID, bytes 封包字节 |
| Fatal | 7 | str text |

**Stats（1 Hz，字段顺序必须逐一对应原版 `SendStats`）**：
```
bool  isSendListRunning
bool  isRobotListRunning

i32   发送条数 → 每条: guid SID + i64 ExecutionCount + i64 Success + i64 Fail

          FilterIntercept_CNT, FilterDisplay_CNT, FilterNoDisplay_CNT

i64 × 11  封包计数: TotalPackets, Send_CNT, SendTo_CNT, Recv_CNT, RecvFrom_CNT,
          WSASend_CNT, WSASendTo_CNT, WSARecv_CNT, WSARecvFrom_CNT,
          Total_SendBytes, Total_RecvBytes
```
（注：`FilterPacket_CNT` 不在其内——那是外壳 FlushToFeed 数的。）

### 4.4 封包帧格式（pkt 管道，对应 PacketFrame）

```
i64   id              目标侧自增

i64   socket          SOCKET 句柄（32 位目标高位为 0）
u8    packetType      PacketType 枚举
u8    filterAction    FilterAction 枚举

str   from            "1.2.3.4:5678"
str   to
bytes raw             原始字节
bytes new             仅 flags.bit0 未置位时存在
```

### 4.5 配置快照格式（SetConfig 载荷）

**HookFlags（12 个 bool，顺序固定）**：
`HookWS1_Send, HookWS1_SendTo, HookWS1_Recv, HookWS1_RecvFrom, HookWS2_Send,
HookWS2_SendTo, HookWS2_Recv, HookWS2_RecvFrom, HookWSA_Send, HookWSA_SendTo,
HookWSA_Recv, HookWSA_RecvFrom`
（三个 Support_* 不走快照——是目标自己探测的，随 HookState 上报。）

**Filters（整表，幂等，i32 条数 + 每条 27 字段）**，字段顺序照原版 `EncodeFilters`：

应用时：**旧表同 GUID 的 ExecutionCount 迁移过来**（编辑一条滤镜不清整表计数），

EncodeSends / EncodeRobots（SCollection 里只传执行器要读的 5 个字段：
PacketSocket / PacketType / PacketFrom / PacketTo / PacketBuffer）。

## 5. 注入模式核心（WPEHook.dll）

### 5.1 注入器（外壳侧，对应 EasyHook CreateAndInject 的职责）

对**已运行进程**：
```
OpenProcess(PROCESS_ALL_ACCESS) → VirtualAllocEx(路径长度) →
WriteProcessMemory(dll路径) → CreateRemoteThread(LoadLibraryW) →
WaitForSingleObject → VirtualFreeEx → CloseHandle
```

对**挂起启动**（对应原版 SuspendedLaunch——模拟器/手游要抓启动瞬间的包）：
```
CreateProcessW(CREATE_SUSPENDED) → 同上注入 → 目标内 StartHook 装好钩子后 ResumeThread
```
> ⚠️ 原版实测：唤醒必须发生在注入 DLL 的 Run 线程上（外壳调作用于外壳自己、
> 控制线程调静默无效、NtResumeProcess 直接死）。本版时序照搬 5.5。

**WOW64 注意**：x64 注入器向 x86 目标 `CreateRemoteThread` 会失败——
注入器必须是目标同位数（外壳 x64 注入 x64 目标；注入 x86 目标时启动 32 位辅助进程，
或直接用 NtCreateThreadEx + WOW64 标志，见第 15 节风险 R11）。

**权限**：目标是其他用户/管理员进程时需要 SeDebugPrivilege；外壳以管理员运行（对应原版要求）。

### 5.4 Winsock 探测（对应 DetectWinsock）

- 枚举**本进程**模块表，判定 wsock32 / ws2_32 / mswsock 是否已加载 → 三个 Support_*。
- **挂起启动**的目标在 StartHook 前必须 `LoadLibrary("ws2_32.dll"/"wsock32.dll"/"mswsock.dll")`
  ——挂起进程还没跑加载器，`GetProcAddress` 会抛 DllNotFound，钩子一个都装不上
  （原版实测"钩子装上了却一条都抓不到"）。
- 已运行的目标**只探测、不硬塞**模块（凭空多出一个模块是检测面，原版 R 系列风险）。

### 5.5 注入线程入口与唤醒时序（对应 Hook.RunHeadless，逐条照搬）

```
注入线程（目标内）：
  1. 装配无头核心 WpeCore::Attach(sessionId, 5000ms, suspendedLaunch)
     · 连 3 条管道；连不上 → SelfShutdown（绝不能留着钩子）→ return
  2. WaitForWakeSignal() 挂在这个事件上（与 shutdown 事件二选一）
  3. 置位后调 ResumeThread（若挂起启动）——此时 13 个钩子已装好，第一个包也抓得到
  4. WaitForShutdown() 阻塞挂住线程
```

**核心线程模型（对应 WpeCore 的 5 条线程，全部 IsBackground 等价物=detached）**：
- 钩子线程 = 目标自己的收发线程（不做任何多余事）
- 写线程 `WriterLoop`：环 → pkt 管道，批量 ≤256 条 / 1 MB，等 5ms
- 控制线程 `ControlLoop`：读命令 → Dispatch → 应答；`_dispatching` 标志挂起超时判断
- 事件线程 `EventLoop`：evt 队列 → evt 管道（唯一写 evt 的地方）
- 心跳线程 `HeartbeatLoop`：1s；顺带发 Stats；空闲超 3s → SelfShutdown

**SelfShutdown（外壳没了/连不上，两条路都走这里）**：
`停钩子 → 清环 → 断管道 → 核心休眠`。目标永远不能因为外壳没了而留着钩子。

**重新附加（对应 R6）**：外壳重启后对同一 PID 再注一次，复用核心实例、只换管道，
钩子不卸（环里中间段的包还在，外壳一连上就能接着看）。

### 5.6 钩子体语义（对应 WinSockHook，行为必须逐条一致）

**Send / SendTo 系**：
```
1. 拷贝 lpBuffer[0..Length) → raw
2. DoFilterList(socket, buffer, ptType) → (action, newBuffer)
3. action == Intercept → 直接返回 Length（假成功，不调原函数）
4. 否则调原函数，缓冲换成 newBuffer、长度换成 newBuffer.Length
5. OnPacket(socket, raw, newBuffer, res, type, action, sockaddr, time)
```

**Recv / RecvFrom / WSARecvEx 系**：
```
1. 先调原函数拿到 res
2. res > 0 才处理：拷贝 lpBuffer[0..res) → raw
3. DoFilterList → (action, newBuffer)
4. action == Intercept → 返回 0（对调用方表现为没收到）
5. 否则 newBuffer 拷回 lpBuffer，返回 min(newBuffer.Length, res)
6. OnPacket(...)
```

**OnPacket 的两道早退（顺序不能变）**：
```
if (action == NoModify_NoDisplay) return;
if (action != Intercept && res <= 0) return;
CountPacketInfo(type, newBuffer 长度);   // 计数在目标数，外壳是镜像
if (SpeedMode) return;                   // 极速模式：只数不建列表
ring.Enqueue(...);
```

**WSARecvEx 默认不钩 x64**（与原版一致，避免截断野指针）；可选开启时用
正确签名 `int* flags` 单独写一个钩子体，绝不能复用 Recv 钩子（flags 按值传才正确）。

## 6. 滤镜引擎

### 6.1 数据结构（对应 FilterInfo 27 字段 + 枚举）

```cpp
enum class FilterMode : int32_t      { Normal = 0, Advanced = 1 };
enum class FilterAction : int32_t    { Replace = 0, Intercept = 1,
                                       NoModify_Display = 2, NoModify_NoDisplay = 3,
                                       None = 4, Change = 5 };
enum class FilterExecuteType : int32_t { Send = 0, Robot = 1, None = 2,
                                         Filter = 3, WareHouse = 4 };
enum class FilterStartFrom : int32_t { Head = 0, Position = 1 };
struct FilterFunction {              // 12 位
    bool Send, SendTo, Recv, RecvFrom;
    bool WSASend, WSASendTo, WSARecv, WSARecvFrom;
    bool TCP_Req, UDP_Req, TCP_Resp, UDP_Resp;
};

struct FilterInfo {
    bool     IsEnable;              uint8_t FID[16];
    std::string FName;              int64_t ExecutionCount;   // 只增不清（快照迁移）
    bool     AppointHeader; std::string HeaderContent;
    bool     AppointSocket; std::string SocketContent;
    bool     AppointLength; std::string LengthContent;
    bool     AppointPort;   std::string PortContent;
    FilterMode FMode; FilterAction FAction;
    bool     IsExecute; FilterExecuteType FEType; uint8_t Execute_GUID[16];
    FilterFunction FFunction; FilterStartFrom FStartFrom;
    bool     IsProgressionDone, IsProgressionContinuous;
    int32_t  ProgressionStep; bool IsProgressionCarry; int32_t ProgressionCarryNumber;
    std::string ProgressionPosition; int32_t ProgressionCount;
    std::string ExcludePosition, RandomPosition;
    std::string FSearch, FModify;              // 搜索串 / 替换串（十六进制文本）
};
```

### 6.2 无锁读（对应 FilterEngine.PublishSnapshot）

- 目标侧持有一份**不可变数组**，`std::atomic<const FilterInfo*>` 换指针发布。
- 钩子线程每次进 `DoFilterList` 先取一次指针用到底（**全程不加锁**）——
  换配置时老数组被上一拍握着，安全用完即可。
- 应用快照时：先按 GUID 存旧 ExecutionCount → 建新表 → 原子换指针 → 替换运行表。

### 6.3 DoFilterList / DoFilter 语义（对照 Operate.cs，逐条照搬）

```
DoFilterList(socket, buffer, ptType):
  filters = FilterEngine::Snapshot();  // 取一次用到底
  for each fi in filters:
    action = DoFilter(fi, ...)
    if action != None:
      if action ∈ {Intercept, Change, NoModify_Display, NoModify_NoDisplay}
        或 执行方式 == Priority:
          return action（bNewBuffer 为空时取原缓冲）
  bNewBuffer = 原缓冲;  return 最后非 None 的动作（或 None）
```

```
DoFilter(fi, socket, buffer, ptType, sAddr):
  1. CheckFilter_IsEffective(...) 不通过 → None
     · 校验：IsEnable、FFunction 含 ptType 对应位、AppointSocket/Port/Header/Length 匹配
  2. 匹配：
     · Normal  → CheckFilter_IsMatch_Normal(fi, buffer)   // FSearch 十六进制串查找
     · Advanced→ CheckFilter_IsMatch_Advanced(...) → 命中位置列表 MatchIndex
  3. 按 FAction 分支：
     · Replace：fi.IsProgressionDone=false；
        Normal → Replace_Normal(fi, buffer)；Advanced → 对每个 MatchIndex 位 Replace_Advanced；
        （IsProgressionDone && IsProgressionContinuous → ProgressionCount++）
     · Change：tempBuffer = ChangePacket_Filter(fi)（FModify 十六进制串替换）
     · Intercept / NoModify_Display / NoModify_NoDisplay：bDoFilter=true
  4. IsExecute && Execute_GUID 非空：
     · Send → SendExecute(GUID)
     · Robot → RobotExecute(GUID, {FilterSocket: iSocket})
     · Filter → DoFilter(GetFilter_ByGuid(GUID), ...)   // 嵌套执行
     · WareHouse → OnStore(GUID, tempBuffer 或原缓冲)    // 只送"仓库+字节"，落库在外壳
     bDoFilter = true
  5. bDoFilter → faReturn = FAction; ExecutionCount++;
     全局计数 ++（FilterReplace_CNT / FilterChange_CNT / FilterIntercept_CNT /
                 FilterDisplay_CNT / FilterNoDisplay_CNT / FilterExecute_CNT）
     非极速模式 → DoFilterLog(...)
```

> **执行方式（Priority / 全部执行）** 是外壳侧一个全局配置，语义：
> `Priority` 模式下命中即停；否则遍历全部滤镜、取最后一个动作。此配置随 Runtime 快照下推。
>
> **完整匹配/替换算法的权威来源**：`Operate.cs` 的 Filter 区
> （`CheckFilter_IsMatch_Normal` / `CheckFilter_IsMatch_Advanced` / `Replace_Normal` /
> `Replace_Advanced` / `ChangePacket_Filter` 及递进字段的每一步读写）。
> 移植时必须逐行对照原文，这里不重述算法细节——因为任何一行偏差都会改变滤镜行为。

## 7. 发送与机器人执行器

### 7.1 发送执行器（对应 SendExecute / SendInfo）

- 数据模型：`SendInfo{ SID(guid), 名称, 启用, 发送集 SCollection, 间隔, 执行计数... }`
- 发送集元素只读 5 个字段：`PacketSocket / PacketType / PacketFrom / PacketTo / PacketBuffer`
- 执行 = 循环调 `SendPacket(socket, type, from, to, bytes)`（在**目标进程内**调，
  套接字句柄属于目标）；记录 执行次数/成功/失败。
- **执行器留在目标里**：滤镜可以触发 Send（那条路本来就在目标的收发线程上）；
  外壳只负责启停与显示，启停前置条件（列表非空、没在跑）不能散成两份。

### 7.2 机器人执行器（对应 RobotExecute / RobotInfo）

- 数据模型：`RobotInfo{ RID(guid), 名称, 指令序列, 执行计数... }`
- 指令集（照原版）：
  - 发包（SendPacket，含 socket/type/from/to/bytes）
  - 延迟（毫秒）
  - 循环（次数 / 条件）
  - 模拟键鼠（SendInput；键名支持 ctrl/control/alt/menu/shift/shiftkey 等修饰键）
  - 控制字：`Enable / Disable`（开关列表）、`SendList / RobotList / FilterList`
    （启动另一组执行器的引用）
- 机器人可带参数 `FilterSocket`（滤镜触发时传入命中套接字）。
- 机器人在目标进程内跑专用线程（不是外壳）。

## 8. 代理模式

### 8.1 SOCKS5 服务器（对应 SuperSocket 版 SocksProxyServer）

原版基于 SuperSocket 的接收过滤器切帧（`Socks5ProxyReceiveFilter`），帧 Key 分四类：

| Key | 阶段 | 处理 |
|---|---|---|
| Handshake | 握手 | 版本/方法协商（支持无认证 + 用户名密码认证） |
| Auth | 认证 | 校验凭据 |
| Command | 命令 | CONNECT / BIND / UDP ASSOCIATE |
| Forward | 转发 | 数据转发（TCP） |
| Control | 控制 | 会话内控制帧 |

C++ 实现：纯 WinSock 手写 SOCKS5 状态机（无第三方依赖更贴近原版），
每个客户端连接一个 `ProxySession` 线程/状态机；UDP 走 ASSOCIATE + 中继
（对应 `ProxyUDP` / `ProcessUdpReceive`，UDP 套接字入池复用）。

**数据流**（对应 ProxySession）：
```
客户端 ──SOCKS5帧──► 外壳 ◄──转发行──► 目标服务器
   ▲                    │                    │
   └────────────────────┴────────────────────┘
    每帧经过：滤镜（DoFilterList）→ 命中则替换/拦截 → 转发
    入站/出站方向分别标记 TCP_Req/TCP_Resp、UDP_Req/UDP_Resp（对应 FilterFunction 后 4 位）
```

### 8.2 HTTPS 中间人解密（对应 SunnyNet）

- **动态 CA**：首次运行生成自签根 CA（RSA/ECC），用户把根证书装进受信根
  （原版是"代理模式连 HTTPS 也能明文呈现"）。
- **按主机签发**：CONNECT 443 时对目标主机动态签发临时证书（内存中完成）。
- **双向解密**：与客户端建立 TLS（用动态证书），与服务器建立 TLS（正常验证），
  中间流转明文，过滤镜，再加密转发。
- C++ 用 OpenSSL：`SSL_CTX` × 2（客户端侧 + 服务器侧）、`SSL_accept` / `SSL_connect`、
  证书生成用 `X509` / `EVP_PKEY` API。**这是工作量第二大的模块**（仅次于 UI），
  建议单独立里程碑（M4，见第 14 节）。

### 8.3 代理模式的滤镜来源

- 从封包"右键 → 生成滤镜"创建（滤镜名 = 服务器地址 + 长度，如 `101.227.22.133:443 [180]`，
  照原版 `AddFilter_ByProxyInfo`）。
- 与注入模式共用同一份滤镜表、同一个 `DoFilterList`、同一套统计。

## 15. 风险清单

**原版已识别、本版必须继承的红线**：

- **R2 目标进程足迹**：目标里只允许 `WPEHook.dll + MinHook + CRT`。
  原版用 GetFootprint 命令量足迹，本版同样实现该诊断命令。
- **R4 DPI**：目标进程里**禁止**调 SetProcessDPIAware（会改目标坐标系）。
- **R6 重新附加**：外壳重启后对同 PID 再注一次必须复用核心、只换管道、不卸钩。
- **R8 线程池**：目标内禁止线程池（专用线程）；禁止任何阻塞目标的调用。
- **管道缓冲**：pkt/evt 管道外壳侧缓冲有限（原版 evt 64KB），事件必须走
  **有界队列 + 专用线程**，满了丢最旧并计数、**绝不阻塞目标的 send/recv**。
- **无声丢包比阻塞更糟**：丢事件/丢包必须计数并出声（日志/界面"丢弃 N"）。
- **x64 WSARecvEx**：默认不钩；可选钩时用正确签名单开钩子体。

**C++ 版新增风险**：

- **R11 WOW64 注入**：x64 注入器向 x86 目标 CreateRemoteThread 失败——
  需要 32 位辅助注入器或 NtCreateThreadEx + WOW64 标志；测试矩阵必须覆盖 x86 目标。
- **R12 加载器锁**：DllMain 禁止做任何事；全部初始化放注入线程入口
  （否则与目标自身 LoadLibrary 死锁）。
- **R13 与目标已有钩子冲突**：MinHook 内联钩子与杀软/反作弊/EasyHook 并存时可能互踩；
  卸载钩子时按原函数字节恢复（MinHook 已处理），目标有自校验时风险自担。
- **R14 受保护目标**：VMP/Themida/反调试目标可能拒绝注入或崩——属预期行为，
  不做对抗（原版同类说明："带反作弊的游戏可能封号，只用自有/已授权目标"）。
- **R15 钩子重入**：滤镜里若触发 Socket 调用（如 SendPacket 经非钩函数路径），
  防止死循环——用 TLS 标记"当前在钩子体内"，原函数调用一律走 trampoline。

### 16.2 关键 C++ 骨架（可直接落地的起点）

**MinHook 钩子 + 滤镜 + 入环（send 系，对照 5.6）**：

```cpp
static int (WINAPI* Real_send)(SOCKET, const char*, int, int);

int WINAPI Hook_send(SOCKET s, const char* buf, int len, int flags) {
    const uint8_t* raw = (const uint8_t*)buf;
    FilterAction action; std::vector<uint8_t> newBuf;
    action = FilterEngine::DoFilterList(s, raw, len, PacketType::WS2_Send);
    int res;
    if (action == FilterAction::Intercept) {
        res = len;                                  // 假成功，不调原函数
    } else {
        res = Real_send(s, (const char*)newBuf.data(), (int)newBuf.size(), flags);
    }
    WpeCore::OnPacket(s, raw, newBuf.data(), (int)newBuf.size(), res,
                      PacketType::WS2_Send, action);
    return res;
}
// 启动：HookManager::Create("ws2_32.dll", "send", Hook_send, (void**)&Real_send);
```

**环形缓冲（语义照搬 PacketRing）**：

```cpp
class PacketRing {
    std::mutex m_; std::deque<PendingPacket> q_;
    std::condition_variable cv_; size_t maxCount_; int64_t maxBytes_;
    int64_t bytes_ = 0; std::atomic<int64_t> dropped_{0};
public:
    void Enqueue(PendingPacket p) {                 // 永不阻塞
        { std::lock_guard lk(m_);
          q_.push_back(std::move(p)); bytes_ += p.Size();
          while ((q_.size() > maxCount_ || bytes_ > maxBytes_) && q_.size() > 1) {
              bytes_ -= q_.front().Size(); q_.pop_front(); dropped_++; } }
        cv_.notify_one();
    }
    // DequeueBatch：无数据时 cv_.wait_for(waitMs)；Reset/Wait 之间再看一眼防漏醒
};
```

**注入器（已运行进程）**：

```cpp
bool InjectIntoProcess(DWORD pid, const wchar_t* dllPath) {
    HANDLE h = OpenProcess(PROCESS_ALL_ACCESS, FALSE, pid);
    size_t n = (wcslen(dllPath) + 1) * sizeof(wchar_t);
    void* remote = VirtualAllocEx(h, nullptr, n, MEM_COMMIT|MEM_RESERVE, PAGE_READWRITE);
    WriteProcessMemory(h, remote, dllPath, n, nullptr);
    HANDLE t = CreateRemoteThread(h, nullptr, 0,
        (LPTHREAD_START_ROUTINE)LoadLibraryW, remote, 0, nullptr);
    WaitForSingleObject(t, INFINITE);               // 挂起启动：先不 Resume，见 5.5
    VirtualFreeEx(h, remote, 0, MEM_RELEASE);
    CloseHandle(t); CloseHandle(h);
    return true;
}
```
