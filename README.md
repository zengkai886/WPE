# WPE64 C++ 重写工程 · 配置加密接线开发中

**当前已经有真实的 C++ → SQLite → 原 Vue 数据闭环，不再只有展示界面；但还不是完整 WPE，也没有完成“所有数据接通”。**

版本栏为 `C++ DATA-dev`。原版 217 个 RPC 中，目前注册了 **74 个数据方法 + 10 个宿主方法**；其中包含只接设置、只接部分分支或返回未运行状态的方法，**84/217 不是功能完成率**。剩余 133 个原方法名未注册，调用明确报错。完整清单见 `docs/全部217个接口接线清单.csv`。

当前增加四父列表导入导出、原版加密互通、五组部分备份与受原生文件选择授权约束的密码验证。准确范围见 `docs/配置加密接线进度.md`，无人值守状态见 `docs/无人值守接续.md`。**不是完整备份或全功能程序；当前不另发阶段 ZIP，旧“导出剪贴板版”不含这些新增代码。** 历史 `exchange-*` / `editor-*` / `data-*` 证据只对应各自当时版本。

## 开发依据与不变项

- 生效需求：`docs/用户提供-重写工程文档-更新版.md`，对应用户上传的 `WPE x64 C++ 重写工程文档 (1).md`。
- 主方案：**C++20 + Win32/WebView2 宿主 + 全部原 Vue**，不重画页面，不换成 Java 或 Qt。
- 原始 Vue、TypeScript、语言、静态资源、远程页面共 **555 个文件**逐个哈希不变，其中 **70 个 Vue 文件**。
- 产品不启动原 C# 程序，不依赖其业务程序集；C# 只用于独立测试参照。
- SQLite 3.46.1 与 WebView2 Loader 静态链接；WebView2 **Runtime 仍为外部运行依赖**，没有伪称打入 exe。
- 原 ZIP、两份需求文档保持不变，版本和哈希见 `contracts`。

## 运行

解压 `WPE64-Cpp-导出剪贴板版.zip`，双击 `wpe64-app.exe`。不要只复制 exe，旁边的 `wwwroot` 是原前端必需资源。需要 Windows x64 和 WebView2 Runtime；本机测试 Runtime 为 `153.0.4234.32`。

查看数据列表：进入原 **代理模式工作区**，点击左侧滤镜、发送、机器人或仓库列表。进入工作区不等于启动了代理，底栏仍是未启动。可以新增/保存列表数据；不能用本开发版开始实际抓包或代理。

默认数据位置：

```text
exe 所在目录/
  wwwroot/                  原预构建前端
  runtime/                  运行后生成的数据目录
    2.3.0/WPE.db             真实 SQLite 业务数据库
    ...                     WebView2 浏览器数据
```

**重要：`runtime` 现在同时含业务数据库，不再是可以整体删除的“缓存”。清理或升级时请保留/备份 `runtime/2.3.0/WPE.db`，关闭程序后再复制。** 发布包不含测试数据库、浏览器缓存或演示记录；第一次启动是空业务列表。目前同一数据目录请只运行一个实例，多实例协调尚未实现。

可显式指定资源与独立数据目录：

```powershell
& '完整路径\wpe64-app.exe' --assets '完整路径\wwwroot' --data-dir '完整路径\我的WPE数据'
```

不要将它指向唯一一份生产数据库。尚未完整验证所有旧版本结构、全部 20 张表或升级路径。

## 构建与验证

需要 Visual Studio 2022 C++ Build Tools（x64/x86）、Windows SDK、CMake ≥ 3.24、.NET SDK 及 .NET Framework 4.8。C# 仅是测试依赖，不是产品运行依赖。

```powershell
& 'E:\codex\2026-09-17\bi-a\outputs\WPE64-Cpp\build-test.ps1' `
  -BuildRoot 'E:\codex\2026-09-17\bi-a\work\cpp-data-check'
```

源码移动后相应调整路径。`-BuildRoot` 必须位于源码目录之外。每次新建 `run-<GUID>`，默认构建并验证 x64 和 Win32；桌面宿主仅构建 x64。工程 C++ 以 `/W4 /WX` 编译，第三方 SQLite C 源码不套用工程的 C++ 警告规则。

请选择较短的构建目录，不要放在多层 GUID 解压目录下。发布复验曾因 MSBuild 的 260 字符路径限制在编译器探测阶段失败；改用工作区内较短的独立构建根目录解决，原失败保留为 `evidence/editor-archive-long-path-failure.log`。

以下是历史已发布 exchange 基线的验证，**不是当前完整功能验收**。当前配置加密专项和 fresh 双架构结果见 `docs/配置加密接线进度.md`、`docs/无人值守接续.md`、`evidence/config-*`：

- **x64 / Win32 各 9/9 CTest**；每架构 **229 项编辑检查**，包含 **184 条原 C# 实际生成的连续编辑参照**，不拿 C++ 自己的输出当标准。
- 原数据服务的 **440 项检查 / 120 条滤镜参照**继续通过；XML、草稿、封包共享引用、锁库回滚、65 MiB 合法文件、Unicode 数字和 GUID 边界另有本段回归。
- 每架构 **74,684 条协议参照 / 76,618 条断言**、600 个原 C# 反向解码封包、6,416 条队列状态对拍。
- 本段新增 41 项导出检查：原版逐字节黄金、混合换行/Unicode/XML 转义、待导出对象别名、计划清理与权限保留；真实剪贴板隔离站测试含延迟渲染与 owner 消息泵。
- 原 Vue 导出/不加密按钮、密码拒绝、HexView Ctrl+C/Ctrl+V、仓库复制按钮通过。UI 层剪贴板使用内存隔离入口，真实 OS 剪贴板另测，不能混称端到端系统剪贴板 UI 测试。
- 真正的原 Vue 按钮链路：发送导入→原 HexView 键入 AA→Socket 99→保存；仓库导入/取消清空/改名；机器人循环开始→延迟 25→循环结束→保存→取消额外草稿。
- 关闭重开后，发送字节/Socket、仓库名称/条目、机器人三条指令以及原滤镜 GUID/名称/启用状态/负偏移均恢复。
- 555 原资源文件 / 70 Vue 哈希不变。产品不调用原 C# 业务后端。

**文件选择测试边界**：自动测试采用固定路径选择入口，后续是真实文件读取、解析、原 RPC、数据库、列表及成功通知；不冒充 Windows 选择框自动点击验收。正常模式使用原生 IFileOpenDialog / IFileSaveDialog。多语言提示与实际选择框仍待完整人工回归。

历史 exchange 构建证据：`evidence/exchange-run-manifest.json`、`exchange-full.log`、`exchange-host-self-test.json`、`exchange-host-restart.json`。审查报告：`REVIEW-exchange-wiring.md`。原程序集参照重生成方法：`tests/data_oracle/README.md`。

源码 ZIP 在**无 .git 的新目录**完整重建，运行包使用该构建的 x64 exe 并从包内默认 wwwroot 通过独立自测。复验结果见 `exchange-archive-run-manifest.json`、`exchange-archive-full.log`、`exchange-package-self-test.json`；Git 只是可选来源信息，不是构建依赖。

`--self-test '报告目录'` 会写入测试记录，**只能配合新的独立 --data-dir 使用**，不要指向常用数据库。自测不注入、不抓包、不监听、不修改系统代理或安装证书。

已知边界：损坏 XML 采用完整解析后原子应用，与原版某些错误路径的部分导入不同；禁止 DTD、嵌套深度上限 64。通用确认及选择框标题未逐语言对齐。隐藏窗口置顶在本机有历史不稳定且根因未定位；topmostProbe 和 windowRoundTrip 逐次记录真实通过或失败，不阻断编辑验收，也不因单次通过计为窗口完整验收；扩展自测曾超过旧 30 秒预算，现为 90 秒。失败记录保留，不能据此声称全体验稳定或所有页面均验收。

- `src/shell`：Win32/WebView2 宿主、异步 JSON 桥、数据库与数据服务。
- `tests`：原版对照运行器、固定参照、回归测试。
- `frontend` / `wwwroot` / `remote-web`：原前端源码 / 原预构建前端 / 原远程页面，未改动。
- `contracts`：需求、原接口/表结构、接线状态、依赖和文件哈希。
- `third_party`：固定版本 JSON、WebView2 SDK 和 SQLite；附许可证或源文件许可声明。
- `evidence`：分阶段测试记录。历史记录不是本轮结果，当前配置增量以 `config-*` 为准，`exchange-*` 为历史记录。
- `REVIEW-config-wiring.md`：本轮 Standards / Spec 双轴审查、已修复问题和未验收边界。

`wwwroot` 是原压缩包自带产物，本次未重新构建或改写前端。实际显示截图见 `evidence/exchange-original-vue.png`，不是界面设计稿。

实现参考：[WebView2 本地资源映射](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2_3)、[WebView2 安全建议](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/security)、[SQLite 连接接口](https://www.sqlite.org/c3ref/open.html)、[SQLite 事务](https://www.sqlite.org/lang_transaction.html)。

原发送编辑器的一个特殊行为：已有 PacketInfo 共享引用，编辑已有字节/Socket 后取消外层发送窗口仍保留内存修改；集合的导入、删项和排序是可取消草稿。详见本段进度文档，不能笼统理解为取消回滚全部对象。

导出取消须区分：保存选择框取消、桥超时/传输失败/导航取消不会写文件；**原 Vue 密码框的 Esc 与“不加密”发送同一个成功 null，按原行为会导出明文**。未改原 Vue，所以不能宣称所有取消均不导出。系统剪贴板延迟渲染在独立线程等待，正常 UI 不等待；关闭程序仍会等待正在进行的 Windows 剪贴板调用返回。
